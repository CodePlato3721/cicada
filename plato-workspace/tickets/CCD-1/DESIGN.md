# DESIGN.md

## Requirement Summary
把 cicada 项目从纯 JavaScript 改写为 TypeScript。先在 `tests/e2e` 下建立 e2e 冒烟测试，作为迁移前后行为不回归的基准；随后完成 JS → TS 改写，改写后需能通过该冒烟测试。

## Design
先建冒烟测试、再动迁移，用测试兜住迁移过程中不引入行为回归。

- **冒烟测试范围**：不连接真实 Discord 服务器、不走语音接收/VAD 切句这两个环节，而是直接从"已有一段音频文件"切入，驱动 STT → 翻译 → TTS 这条核心链路（调用真实外部 API，不 mock）。断言只到"最终生成出了一个 `.wav` 文件"这一层，不校验音频内容/文本内容的正确性——语音语义正确性不是这次迁移要验证的东西，这里只是拿它当"链路没跑断"的信号。
- **迁移范围**：项目里所有 `.js` 文件全部转 `.ts`，没有例外——包括长期运行的 bot 主进程代码（`src/index.js` 及其 `application`/`adapter` 依赖），也包括之前在日志规范化里被排除在外的一次性 CLI 脚本（`scripts/*.js`、`src/deploy-commands.js`）。
- **构建与部署**：新增 `tsc` 编译步骤,产出 `dist/`,pm2 托管进程改为运行编译产物,不引入 `ts-node`/`tsx` 之类的运行时直跑 `.ts` 方案——避免给这台 1vCPU/1GB 的小 droplet 增加运行时开销。
- **验收方式**：迁移完成后跑通 `tests/e2e` 下建好的冒烟测试,视为改写没有破坏核心链路的可运行性。
